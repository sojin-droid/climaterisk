## 2. CLIMADA 조사 — 반영도 평가

CLIMADA(코어 ≥6.1 + petals ≥6.1 pip)에서 의사결정에 쓰이는 표면 대비:

**충실히 반영된 것** (코드 확인, 상세는 CLIMADA_COVERAGE.md)
- 엔진: `ImpactCalc`(AAI·eai_exp·빈도곡선·현재↔미래 델타) + **yearset 연손실 분포** +
  **Warn 경보단계** + 재현주기 기록 상한(기록의 ½, 외삽 금지)
- 적응: `CostBenefit`(조치 편익/비용·NPV·위험이전)
- 불확실성: **Saltelli–Sobol**(unsequa와 동일 엔진 SALib 직결, S1/ST)
- 노출: 점·폴리곤·선 자산 + LitPop·래스터(WorldPop)·OSM·BlackMarble·GDP2Asset·작물 + 인구
  (headcount 분리 — 사람을 돈으로 집계하지 않음)
- 하자드: Data API 미래셋(rcp×연도) + 로컬 카탈로그 우선 + 커스텀 온램프(표준화 격자→HDF5)
- 취약성: 스튜디오 편집 + **발표 문헌 프리셋**(Eberenz 지역 v½ 10종, JRC 대륙 홍수 6종) +
  EM-DAT 보정 러너 + 유럽폭풍 Schwierz↔Welker 토글
- 예보: petals `TCForecast`(ECMWF 앙상블, 비시즌 정직 저하)
- 경계: 백엔드가 CLIMADA를 import하지 않는 GPL 격리(테스트로 고정)

**의도적으로 안 한 것** (정직한 부재)
- 운영 예보 외 가짜 예보 없음 · 미검증 재해는 "ingestion 필요" 에러로 명시 ·
  재현주기 외삽 금지 · 도시 내수침수(pluvial)는 전지구 표준 하자드가 없어 구조적 미지원

**CLIMADA에 있는데 안 쓰는 것 중 실질 가치가 있는 것** → G1·G2·G6(아래). 나머지
(unsequa 클래스 API, TCTracks 생성 UI, 이벤트 드릴다운)는 우선순위 낮음이 타당하다.

## 3. 방법론 갭 (G1–G8) — 이 코드 기준 재검증 완료

각 갭: **방향**(과대/과소평가), 근거, 해법, 공수. 7월 실측치는 유실 사본에서 나온 것으로
"(7월 실측)"으로 표기 — 재이식 시 재실측해 문서화할 것.

### G1. 태풍 기본 취약성이 지역 미보정 — **한국 과대평가(수 배)** 〔심각도 최상 → **코드 해소 2026-09-07**〕

> **반영:** `worker/climaterisk_worker/vulnerability.py::resolve_tc_vhalf` — 자산 ISO3 → CLIMADA
> `get_countries_per_region` 기반 Eberenz 지역(프리셋 `countries`) → 번들 프리셋 v½(KOR=WP4 190.5).
> 스튜디오 override > (옵션) 보정 기록 > 지역 프리셋 > 클래스 기본값. 태풍 러너·비용편익·불확실성·
> 예보·공급망 공용. 테스트 `tests/test_vulnerability_defaults.py`. **미검증**: 국내 손실 대조는 C2/C5.
- 현상: 신규 자산 기본 클래스(residential)의 Emanuel `v_half=70`, 전 클래스 70–110.
  국가와 무관하게 적용된다. Eberenz 2021의 한국(WP4 북서태평양) 보정값은 **TDR 190.5 /
  RMSF 135.6** — v½가 낮을수록 취약하므로 기본값은 한국 자산을 크게 과대평가한다.
- 근거(7월 실측): 전역 기본 74.7로도 태풍 매미(2003) **바람 성분만으로 관측 총피해($3.5B)의
  210%**가 나왔다. 70은 그보다 더 취약한 설정이다.
- 완화 요소: Eberenz 프리셋이 스튜디오에 있다(클릭 시 정확). 문제는 **기본 경로**.
- 해법: `country_iso`(자산 역지오코딩 또는 명시)로 Eberenz 지역 v½ **자동 스위칭**.
  petals `ImpfSetTropCyclone.calibrated_regional_vhalf(approach, q)` 네이티브 존재.
  (주의: `get_countries_per_region`에 조회 버그가 있어 7월엔 `CountryCode.ALPHA3.value`로
  우회했다.) 공수: 소(러너 1곳 + 테스트).

### G2. 홍수 계열 기본 곡선 = JRC **Europe** 고정 — **한국 과소평가(16–31%)** 〔심각도 상 → **코드 해소 2026-09-07**〕

> **반영:** `vulnerability.py::resolve_flood_mdr` + `physical.py::_flood_impf_set` — 자산 ISO3 → CLIMADA
> `NatRegIDs.csv` 기반 JRC 지역 → 번들 프리셋 곡선(KOR=Asia). 하천홍수·해안침수·해일 3계열 공용,
> 미지원 국가는 클래스 곡선(일반 폴백)으로 명시. 주거 업종 한정. **미검증.**
- 현상: 기본 residential `flood_mdr = [0, .25, .40, .60, .75, .85, .92, .95]`는 JRC
  Huizinga 2017 **유럽** 주거 곡선과 4 m까지 동일하고(5–6 m는 .92/.95 vs 프리셋 .95/1.0)
  하천홍수·해안침수·TC해일 3계열이 국가 불문 이 계열을 쓴다. JRC **아시아** 곡선은 16–31% 높다(7월 실측: 인천 해일 EAD +18.4%).
- 완화 요소: 6대륙 JRC 프리셋 존재(수동).
- 해법: `country_converter`로 대륙 판정 → `ImpfRiverFlood.from_jrc_region_sector(region,
  sector)` 자동 선택(하드코딩 금지 — 7월 구현은 KOR→Asia·USA→N.America·DEU→Europe 등
  스위칭을 검증했음). 공수: 소–중(3계열 공통 헬퍼).

### G3. 산불 무임계 sigmoid — **저강도 시즌 과대(자릿수급)** 〔심각도 상〕
- 현상: `x0=325 K, k=0.035`의 로지스틱이 295 K부터 피해를 부여 — 발화 임계가 없어
  300 K(비화재 수준)에서도 ~12% 피해율. 7월 실측: Lüthi(EM-DAT 보정) 형태로 바꾸면 인천
  광역 EAD **30,734 → 3,671 명-등가/yr**(약 8배↓), 특정 구는 4.84%/yr → 0.35%/yr.
- 주의점(7월 조사): Lüthi 보정본은 WFsingle 하자드·해상도 의존(i_half 295/409/484 K,
  1 km 값은 축퇴로 기각) — 직접 대입이 아니라 **보정 형태 채택 + 해상도군 밴드**가 정답.
- 해법: 하자드 격자 간격을 측정해 대표 i_half 선택 + 밴드 병기. 공수: 중.

### G4. 카탈로그 재해 7종의 지시적 램프 + 파라미터 차용 〔심각도 중〕
- 현상: hail·drought·low_flow·landslide·crop_yield·heatwave·tc_rain은 임의 램프 impf를
  쓰며, 스케일 파라미터로 **산불용 `wf_max_mdd`를 차용**한다. 물리 하자드(TC호우 R-CLIPER)
  까지 지시적 곡선으로 평가된다.
- 해법(단계): ① 결과 카드에 "지시적 곡선" 성숙도 라벨(즉시) ② 재해별 문헌 곡선 교체(장기).
  tc_rain은 JRC 홍수 곡선 계열로의 승격 후보. 공수: ① 소 / ② 재해당 중.

### G5. 태풍 복합재해 미결합 — 합산 왜곡 + 호우 갭 〔심각도 중상〕
- 현상: tc_surge가 **별도 재해**라 바람과 해일을 같은 이벤트에서 결합하지 않는다
  (단순 합산은 포화 무시로 과대, 미실행 시 과소). 호우(TCRain)는 지시적 곡선(G4)이라
  실질 미반영.
- 근거(7월 실측): 한국 TC는 복합재해 — wind⊕surge 결합이 관측 총피해의 **1.5%(루사,
  강우지배)~20%(매미, 바람지배)**만 포착. 즉 현행 태풍 수치는 **하한**이다.
- 해법: 이벤트 정렬 결합 `f_tot = 1−(1−f_wind)(1−f_surge)` 옵션 + **포착률 캐비엇을 결과에
  상시 부착**(계산이 아니라 검증 산출값 인용). 공수: 중.
- 부수 캐비엇: bathtub 해일은 **방조제 미반영** — 저지대 해안 대도시에서 두 자릿수 %/yr까지
  부풀 수 있음(7월 부산 실측: 서구 28.2%/yr). 해일 결과는 스크리닝 등급으로 제한할 것.

### G6. 단일값 보고 — 취약성 밴드 부재 〔심각도 중상〕
- 현상: Sobol이 분산의 83%를 취약성으로 지목했는데, 정작 결과는 v½ 한 점의 단일 AAI로
  보고된다. Monte-Carlo 히스토그램은 있으나 **문헌 보정세트 간 구조적 불확실성**(Eberenz
  RMSF↔TDR 3.3배, 7월 실측)을 표현하지 못한다.
- 해법: 발표 세트 멤버를 동시 산출해 **범위로 병기**(RMSF↔TDR, JRC 업종, 산불 해상도군,
  폭풍 Schwierz↔Welker — 마지막은 토글이 이미 있어 밴드화 최소 공수). 임의 ± 밴드 금지,
  **발표된 세트만** 멤버로. 공수: 중.

### G7. 도시 내수침수(pluvial) 구조 공백 〔구조적 — 명시 유지〕
- 한국 도시 주력 리스크일 수 있으나 전지구 표준 하자드가 없다. "곧 지원" 포장 금지.
- 부분 대응: 환경부 도시침수지도(RISK_REGISTER C3, 비상업 라이선스) → 내부 검증 전용
  카탈로그 주입. river_flood=0을 "홍수 무위험"으로 읽지 않도록 해석문 유지(구현됨).

### G8. 사용 등급(use-tier) 선언 부재 〔문서 갭〕
- 해소 못 한 편향(G1–G5)이 있는 동안 결과가 **스크리닝용인지 의사결정용인지** 사용자에게
  선언되지 않는다. 7월엔 SCOPE.md(급성/만성 경계 + 재해별 등급표 + 승급 조건)로 해결했으나
  유실됨. 해법: SCOPE.md 재작성(본 문서 §3이 재료). 공수: 소(문서).

### 우선순위 (효과 ÷ 공수)

1. **G1+G2 지역 자동 스위칭** — 소공수로 최대 편향 제거. RISK_REGISTER C2(재해연보 보정)
   완료 전까지의 안전망이기도 하다.
2. **G6 밴드**(G1 구현에 얹으면 증분 소) + **G8 SCOPE 문서**.
3. **G3 산불 보정 형태**.
4. **G5 서브페릴 결합 + 포착률 캐비엇**.
5. G4 성숙도 라벨(즉시 가능한 소작업) — 순서 무관 병행.

## 4. RISK_REGISTER(C1–C6)와의 관계 — 직교성

| | 본 문서 G1–G8 | RISK_REGISTER C1–C6 |
|---|---|---|
| 대상 | **모델 기본값·구조** (데이터 없이도 고칠 수 있음) | **국내 데이터 주입** (외부 확보 필요) |
| 예 | Eberenz 자동 스위칭, 밴드, 결합 | 재해연보 보정, KMA 1km, 홍수지도 |
| 관계 | C2(국내 보정)가 완료되면 G1은 데이터 기반으로 대체됨. **그 전까지** G1 방치는 수 배 편향을 기본값으로 노출 | C 작업의 검증 대상 수치가 G의 밴드·캐비엇 프레임 안에서 보고되어야 함 |

권장 병행: **G1/G2(며칠) → C2 재해연보 보정(등록표의 1순위)** 순서로 하면, 보정 결과가
나왔을 때 "기본값 대비 얼마나 움직였나"를 밴드 언어로 바로 말할 수 있다.
