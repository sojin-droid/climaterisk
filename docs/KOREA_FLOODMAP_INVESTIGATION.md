# 환경부 홍수위험지도 — `KOREA_LOCAL` 홍수 어댑터 연결 가능성 조사 (Phase 4)

조사일 2026-09-23. 목적: `KoreaLocalFloodAdapter`(현재 `NOT_IMPLEMENTED`)를 실제 국내 홍수위험지도에
연결할 수 있는지 — **데이터 접근권 · 라이선스 · 파일 구조 · 공간좌표 · 침수심 · 재현기간** — 을 먼저 확인한다.
구현은 하지 않았다. 아래 사실은 포털 페이지와 **구조 확인용 샘플 2개(0.9 MB, 8.4 MB)**에서 직접 읽은 것이며,
샘플은 스크래치 디렉터리에만 두고 저장소·데이터 디렉터리에 넣지 않았다.

## 결론 먼저

| 항목 | 결과 | 어댑터에 미치는 영향 |
|---|---|---|
| 접근권 | **로그인 불필요**, `data.floodmap.go.kr` 목록·다운로드 API 공개 | 기술적 장벽 없음 |
| 라이선스 | **공공누리 제4유형 — 출처표시 + 상업적 이용금지 + 변경금지** (포털 저작권 정책 페이지, 공공데이터포털 이용허락범위 모두 동일) | **차단.** 폴리곤을 CLIMADA 해저드 격자로 변환하는 것은 *변경*, 자산 물리위험 평가 서비스는 *상업적 이용*에 해당할 수 있다. 별도 이용허락 전까지 구현하지 않는다 |
| 파일 구조 | SHP(zip), 중권역(`SBSN_CD`) × 빈도 1파일, 각 파일 5행(침수심 등급별 MultiPolygon) | 어댑터 설계에 충분한 정보 확보 |
| 공간좌표 | **EPSG:5186** (KGD2002 / Central Belt 2010, TM, 중앙경선 127°E) | WGS84 변환은 표준 절차 |
| 침수심 | **등급값**(5단계), 연속값 아님 | JRC 수심-피해 곡선을 쓰려면 등급→대표수심 **모델링 결정** 필요 |
| 재현기간 | 국가하천 100/200/500 + 기왕최대; 지방하천 50/80/100/200/500 + 기왕최대; 도시침수 30/50/80/100/500 + 기왕최대 | 확률 해저드로 표현 가능(3–5 RP), 단 "기왕최대"는 RP가 아니다 |

**따라서 `KOREA_LOCAL` 홍수는 `NOT_IMPLEMENTED`를 유지한다.** 코드상 상태 이름은 `NOT_IMPLEMENTED`(어댑터에 데이터가
연결되지 않음)이고, readiness 셀의 `detail`에 차단 사유를 라이선스로 명시했다. UI는 "Korea Local — Not available"로
표시한다.

## 2. 라이선스 — 확인된 문구

포털 저작권 정책(`/main/guide/copyright_policy`):

> 제4유형 [홍수위험지도 해당] — 본 저작물은 "공공누리 제4유형 : 출처표시+상업적 이용금지+변경금지" 조건에 따라 이용할 수 있습니다.

공공데이터포털 이용 조건: "공공저작물 : 출처표시, 상업적 이용금지, 변경금지 (제 4유형)", 비용 무료.

이 플랫폼의 용도에 대한 판단:

| 플랫폼 행위 | 제4유형 조건 | 판단 |
|---|---|---|
| 출처 표시 | 출처표시 | 가능 (`hazard_source`에 기관·데이터셋명 기록) |
| 폴리곤 → 격자 해저드 변환, 등급 → 대표수심 부여, WGS84 재투영 | **변경금지** | 파생저작물에 해당할 가능성이 높다 |
| 자산 포트폴리오 물리위험 평가(EAL·PML)에 사용 | **상업적 이용금지** | 상업 서비스에서는 위반 가능 |

포털 자체 설명도 "지자체의 재해지도 제작, 홍수 관련 보험의 기초자료"를 활용 예로 들지만, 그것이 제4유형 조건을
바꾸지는 않는다. **관리부서(수자원정보센터, 02-590-9977)에 이용허락을 별도로 받기 전에는 어떤 파일도 복사·변환·계산하지
않는다.** 이 조사에서 내려받은 샘플 2개는 구조 확인 후 폐기한다.

## 4. 공간좌표

`.prj`: `PROJCS["KGD2002_Central_Belt_2010", … Transverse_Mercator, Central_Meridian 127.0, Latitude_Of_Origin 38.0,
False_Easting 200000, False_Northing 600000, Scale 1.0, Unit Meter]` → geopandas가 **EPSG:5186**으로 식별.
WGS84(EPSG:4326)로의 재투영은 표준이며, 재투영 후 도형이 CLIMADA 격자(위경도)와 맞는다.

## 5. 어댑터가 만족해야 할 계약 — 라이선스가 풀리면

`docs/korea-hazard-replacement.md` §2·§3의 계약을 이 데이터에 맞춰 구체화한 것. **모두 미구현.**

| 항목 | 이 데이터에서의 구현 방식 | 결정이 필요한 지점 |
|---|---|---|
| `haz_type` / `units` | `"RF"` / `"m"` — JRC 곡선의 x축 | — |
| 강도 | 등급 → **대표수심**(예: 구간 중점 0.25 / 0.75 / 1.5 / 3.5 m, 최상위 등급은 개방구간) | 대표값 선택은 모델링 결정이다. 문서화·감도분석 없이 넣지 않는다. 대안: 등급 하한(보수적) |
| 이벤트 | RP별 1개 — 국가하천 {100, 200, 500} | 3개 RP뿐이라 `calc_freq_curve`의 한계(`max_resolvable_return_period` = 500) 안에서 PML100은 표현 가능. **기왕최대는 RP가 아니므로 제외** 또는 별도 라벨 |
| 빈도 | 초과빈도의 **증분**(플랫폼이 Aqueduct 층에 쓰는 `_incremental_frequency` 규칙) | — |
| 센트로이드 | 폴리곤을 격자로 래스터화(예: 100 m 또는 1 km) 후 격자 중심점; 격자 밖 = 0 | 격자 해상도는 S2·S3 해상도 계약과 함께 결정 |
| 시나리오 | **설계홍수(제방붕괴·월류 가정) 시나리오 — RCP가 아니다.** `served_scenario`에 `"design flood (levee failure assumption), RP set {100,200,500}"`처럼 기록; `requested_scenario`(rcp45 등)와 다르므로 `SCENARIO_MISMATCH`가 되지 않도록 비교 규칙을 정해야 한다 | 기후 시나리오 축이 없는 해저드를 어떻게 세 모델 비교에 넣을지 — 이것이 Phase 4 구현의 핵심 결정 |
| 공간 커버리지 | 중권역 단위 파일 → 포트폴리오 bbox와 겹치는 파일만 로드 | — |
| 출처 | `hazard_source = "환경부 한강홍수통제소 홍수위험지도"`, `hazard_dataset = 파일명`, `hazard_data_version = infoUpdtYm` | — |

한 가지는 지금 말할 수 있다: 이 지도의 "홍수"는 **제방이 실패하는 최악의 시나리오 하에서의 침수 범위**(포털 설명: "실제
하천제방의 안정성과 무관")다. Data API의 ISIMIP 하천홍수(수문 모델 기반 확률 해저드)와는 **다른 종류의 양**이다. 세 모델
비교에서 이 차이는 데이터 차이가 아니라 **정의 차이**로 표시해야 한다.

## 6. 하지 않은 것

* 어댑터 구현, 등급→수심 매핑, 래스터화 — 하지 않음.
* `READINESS["RF"]["KOREA_LOCAL"]` 변경 — `NOT_IMPLEMENTED` 유지, `detail`만 확정 문구로 갱신.

## 8. 2026-11-13 이용 결정과 2026-11-14 연결 (method tier T2)

- **이용 결정 (2026-11-13, 사용자)**: 비영리 싱크탱크의 내부 분석으로, **원문 폴리곤에 자산을 겹쳐 보는 것만** 한다.
  - 폴리곤을 격자화·클립·단순화하지 않는다.
  - 원자료나 변환물을 저장·배포하지 않는다.
  - 출처를 표시한다.
  - §2의 차단 판단(격자 변환 = 변경, 상업 서비스 = 상업적 이용)은 그대로 유효하다. 이 결정은 그 둘을 하지 않는 방식만 허용한다.
- **구현**: `KoreaLocalFloodAdapter`(`READY`, `trial: yes`).
  - 지도는 하천범람지도만 쓴다(국가하천 100/200/500년, 지방하천 100년). 도시침수지도는 내수라 별도 재해로 다룬다.
  - CLIMADA 센트로이드는 **자산 지점 자체**다. 해저드 격자를 만들지 않는다.
- **깊이**: §5의 "등급 → 대표수심" 대신 **범람 경계 지형법**(FwDET, Cohen et al. 2018)을 쓴다. 자산이 범람 범위(5개 등급 폴리곤의 합집합) 안이면, 반경 500 m 안의 범람 외곽선 지반고 중앙값에서 자산 지반고를 뺀다(Copernicus GLO-30).
  - 등급 코드 ↔ 수심 구간 대응이 공개되지 않아(§3), 등급은 **보조 점검**으로만 쓴다. 경계 지형법 깊이의 등급별 중앙값이 등급 코드 순서와 단조이면 일치, 아니면 경고한다(`floodmap_depth.class_monotonic`).
- **가정과 한계**:
  - GLO-30은 표면모형(건물·수목 포함)이다. 그래서 시가지에서는 깊이가 낮게 나온다(보수적 하한).
  - 지도에 없는 소하천은 표현되지 않는다(0 m).
  - 지방하천은 100년 지도만 있어 200/500년에 하한으로 이어 쓴다.
  - 100년보다 잦은 홍수는 표현되지 않는다(기대손실 하한).
  - 지도는 현재 기준 설계홍수(제방 붕괴 가정)라 기후 시나리오가 없다. 그래서 미래 시나리오를 요청하면 `SCENARIO_MISMATCH`로 금액이 빠진다.
- **헤드라인 전환 조건**: `trial` 동안 추천 모델은 `DATA_API_COUNTRY`로 유지한다. 같은 자산에서 ISIMIP(T1)와 비교하고, 등급 보조 점검이 통과하면 `trial`을 뗀다([TIERS.md](TIERS.md) §4).
- **현장 점검 (2026-11-14)**: 국가하천 100년 중권역 3곳(1018, 3011, 2009)에서 범람 범위 안 무작위 60지점씩 계산했다([evidence/floodmap_edge_depth_check_2026-11-14.json](evidence/floodmap_edge_depth_check_2026-11-14.json)).
  - 세 곳 모두 경계 지형법 깊이가 등급 코드 순서대로 올라갔다(보조 점검 통과).
  - 합친 등급별 중앙값은 N330 0.16, N331 0.73, N332 1.21, N333 1.82, N334 5.46 m다(현재 코드). N333만 공식 구간(2–5 m)보다 약간 낮고, 나머지는 공식 구간(0.5 이하, 0.5–1, 1–2, 5 m 이상)에 코드 순서대로 들어간다. 그래서 **N330 = 가장 얕은 등급 … N334 = 가장 깊은 등급**으로 추정되지만, 공식 확인은 아직 없다.
  - 범위 안 지점의 약 20 %는 0 m로 나왔다(대부분 가장 얕은 등급). 표면모형 DEM 때문에 깊이가 낮게 잡히는 것과 일관된다.
  - 계산 시간은 타일이 있으면 중권역당 수 초다. 지형 타일을 처음 받을 때는 수십 분 걸린다(1°×1° 타일 하나에 20–50 MB).

## 9. 2026-11-15 주 방법과 보조 점검을 바꿈

- **이유**: 디자인 작업에서 서울 깊이를 뽑다가, Copernicus GLO-30(건물·수목을 포함한 표면모형)으로 구한 경계 지형 깊이가 서울 고층 지역에서 크게 틀린다는 것을 확인했다. 최대 21 m가 나왔는데, 그 자리의 공식 등급은 2–5 m였다.

  | 자료 | 공식 구간 안에 드는 비율 | 등급별 중앙값 순서 |
  |---|---|---|
  | GLO-30, 농촌 | 45 % | 맞음 |
  | GLO-30, 서울 | 28 % | 맞지 않음 |
  | 국토지리정보원 공개 DEM 90 m(지면모형), 동서울 | 45 % | 맞음 (0.14 / 0.32 / 0.99 / 1.67 / 5.58 m) |

  근거: [evidence/floodmap_seoul_dem_check_2026-11-15.json](evidence/floodmap_seoul_dem_check_2026-11-15.json)
- **주 방법**: 자산을 덮는 가장 깊은 공식 수심 등급을 그 등급의 구간으로 읽는다(≤0.5 / 0.5–1 / 1–2 / 2–5 / ≥5 m). 계산에는 대표값을 쓴다(`physical_risk_config.json` → `flood_map.depth_representative`, 기본 중간값). 5 m 이상 등급은 상한이 없어 `open_class_depth_m`(5.0 m)을 쓴다. DEM은 쓰지 않는다.
- **보조 점검(진단만)**: 범위 안 자산 가운데 최대 200곳에서 경계 지형 깊이를 구해 공식 구간과 맞는지 본다. 지면 DEM이 자산과 경계 표본을 모두 덮으면 지면 DEM을 쓰고, 아니면 GLO-30을 쓰며 그 사실을 기록한다. 경고 조건은 점 20곳 이상에서 구간 안 비율이 0.35 미만이거나 중앙값이 등급 순서대로 오르지 않을 때다. 0.35는 잠정값이다. 결과 숫자는 바꾸지 않고, 모델 탭 기록의 `sub_check`에 남긴다.
- **대표값에 따른 피해율** (JRC 아시아 주거 곡선, `ImpfRiverFlood.from_jrc_region_sector`):

  | 등급 | 구간 (m) | 하한에서 | 중간값에서 | 상한에서 |

  | N330 | 0–0.5 | 0.00 | 0.15 | 0.33 |
  | N331 | 0.5–1 | 0.33 | 0.41 | 0.49 |

  얕은 등급에서 대표값 선택의 영향이 크다(N330: 0–0.33). 하한과 상한으로 기대손실 범위를 함께 내는 일은 후속 작업이다.

## 10. 2026-11-15 헤드라인 전환

- **비교** (표본 포트폴리오 1,000곳, 현재 기후): 같은 자산에 두 모델을 돌렸다. 근거: [evidence/river_headline_comparison_2026-11-15.json](evidence/river_headline_comparison_2026-11-15.json)

  | 항목 | ISIMIP 국가 자료 (T1) | 홍수위험지도 (T2) |
  |---|---|---|
  | 포트폴리오 기대손실(EAL) | $760,597 | $2,081,489 (2.74배) |
  | 100년 빈도에 젖는 자산 | 164곳 | 93곳 (둘 다 젖는 곳 24곳) |
  | 젖은 자산의 100년 수심 | 중앙값 9.18 m, 최대 19.69 m | 0.25 / 0.75 / 1.5 / 3.5 / 5.0 m에 31 / 11 / 18 / 25 / 8곳 |
  | 기대손실 상위 10곳 몫 | 0.43 | 0.73 |

  ISIMIP 수심은 4.6 km 격자 칸의 수심이지 건물 앞 수심이 아니다. 지도는 하천 구간을 따라 자산 하나하나에 닿는다. 두 모델이 젖는 자산이 거의 겹치지 않으므로(24곳) 어느 쪽이 맞는지는 이 비교만으로 가릴 수 없다.
- **결정**: 사용자가 하천 홍수의 헤드라인을 홍수위험지도(`KOREA_LOCAL`, 방법 티어 T2)로 정했다. `trial` 표시를 뺐고, Recommended 모드는 하천 홍수에 `KOREA_LOCAL`을 고른다.
- **현재 기후**(`historical`): 지도 그대로다. 달라진 것이 없다.
- **미래 시나리오**(rcp26/45/60/85와 연도): 같은 지도 수심에 모든 사건의 **빈도**를 한 숫자 f로 곱한다.

  $$ f = \frac{\sum_c EAL_c^{\text{ISIMIP}}(\text{rcp},\ \text{미래 구간})}{\sum_c EAL_c^{\text{ISIMIP}}(\text{rcp},\ 2010\text{–}2030)} $$

  ASCII: `f = 시나리오 구간 EAL 합 / 같은 RCP 2010–2030 EAL 합`. 단위 노출(칸마다 1)을 ISIMIP 한국 격자 모든 칸에 두고, 피해곡선은 모델들이 쓰는 JRC 아시아 주거 곡선이다. 시나리오는 `RF_SCENARIO_MAP`(rcp45 → rcp60)과 구간 `rf_year_range(year)`를 따른다. 같은 RCP·같은 모델 사슬의 2010–2030이 현재이므로(`runner.baseline_groups`와 같은 규칙), 이 구간 자체의 f는 정의상 1이고 내려받지 않는다. 구현: `worker/climaterisk_worker/flood_delta.py`, 계산한 f는 `cache/floodmap/delta_*.json`에 보관한다.
- **가정**: (1) 기후 변화는 **빈도**로만 들어간다. 수심은 현재 지도 그대로다(미래에 더 깊어지는 효과는 없다). (2) f는 전국 하나다. (3) f의 근거인 ISIMIP는 4.6 km 격자와 전국 일괄 곡선이라 지역 편차를 모른다. (4) f는 방어 규칙(전국 2년, 제방)을 적용하지 않은 단위 노출의 비율이다. 오프라인이고 저장된 값이 없으면 f=1로 넘어가지 않고 `NO_HAZARD_DATA`로 표시한다.
- **보조 점검(진단만)**: 시도(SGIS)별로 같은 비율을 구해(시도마다 젖은 격자 칸 20개 이상일 때만) 자산 수로 가중한 시도 f를 전국 f와 비교한다. 차이가 25 %를 넘으면 경고한다(`flood_map.delta_check_tol`). 결과 숫자는 바꾸지 않고, 모델 탭 기록의 `climate_delta.check`에 남긴다.
- **지도의 DEM 보조 점검은 그대로 보인다.** 이 비교에서도 경고를 냈다: 공식 구간 안 비율 32.5 % (기준 0.35), 등급 중앙값 순서는 맞음, GLO-30에서 80곳 중 68곳. 지도의 깊이 구간을 쓰는 주 방법은 바꾸지 않았다(§9).
