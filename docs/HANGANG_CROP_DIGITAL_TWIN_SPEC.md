# 한강 중류 크롭 — 디지털 트윈 설계 명세

> **상태:** 설계 명세 v0.2 (2026-11-01). 구현 전. 구현 주체: 자율 에이전트(Hermes)가 Mac mini에서
> 이 문서와 저장소만 보고 만든다.
>
> **한 줄 요약:** 서울 한강 중류의 **실제 한 구역(8 × 6 km)을 크롭**한다. 지형·건물 발자국·강·도로는
> 공개 데이터(OSM, DEM) 그대로, **구할 수 없는 수치 — 하천 침수심, 건물 가치, 문턱, 인구 — 는 상상값**으로
> 넣는다. 그 위에서 이 저장소의 CLIMADA 엔진이 낼 수 있는 결과 경로가 한 번씩 드러나게 하고, 3D로 본다.
> v0.1(24 × 18 km 합성 도시, 8개 구역)은 "너무 넓고, 합성이 아니라 크롭이어야 한다"는 지적으로 폐기.

## 1. 크롭

- **영역:** 경도 127.00–127.11, 위도 37.50–37.555 (≈ 9.7 × 6.1 km). 한강 본류가 동서로 가로지르고,
  북안에 중랑천 합류부·성수·옥수·응봉 구릉, 남안에 압구정·청담·탄천 합류부·잠실 서측 저지가 들어온다.
  (지명은 **설명용**. 결과를 그 동네의 실제 위험으로 읽지 않는다 — §7 테스트로 금지.)
- **왜 여기:** 작은 범위 안에 ① 양안, ② 지류 합류부 2곳, ③ 표고 2 m 하안 단구와 170 m 구릉이 함께 있어
  **같은 수위에도 침수심이 셀마다 다르고**, ④ 고가치 상업·노후 주거·공단형·지하철 역세권이 섞여
  **같은 침수심에도 손실이 자산마다 다르다.** "모든 곳이 같은 값"이 구조적으로 나올 수 없다.
- **계산 격자:** 100 m (≈ 110 × 60 = 6,600 셀). DEM이 123 m라 더 잘게 쪼개면 거짓 정밀도.
  세 해상도 기록: source = OSM 벡터 + DEM 123 m, stored = 100 m, calculation = 100 m.
- **"실제 격자 4칸" 요구에 대해:** 실제 TC/HW 셀은 크롭 안에 2~3개뿐이고 값이 거의 같다. 4칸(≈15 × 12 km)으로
  넓혀도 TC는 ±2 m/s, HW는 ±1 °C 안에서만 움직인다(서울 전체 측정값). 공간 변별은 **지형 기반 RF와
  자산 이질성**에서 나오므로 작게 유지한다. 넓히는 것은 spec의 bbox 숫자 하나다.

```
          127.00                                            127.11
 37.555 ┌─────────────────────────────────────────────────────┐
        │  옥수·금호 (주거, 구릉 사면 20–80 m)   응봉 ▲170 m      │
        │   중랑천 ↓합류        성수 (공단형·준공업, 단구 5–10 m)  │
        │ ≈≈≈≈≈≈≈≈≈≈≈≈≈≈  한강 본류 (폭 ~1 km)  ≈≈≈≈≈≈≈≈≈≈≈≈≈≈≈ │
        │  압구정·청담 (고가치 상업·주거, 단구 8–15 m)   탄천 ↑합류  │
        │                              잠실 서측 (저지 2–6 m, 상습침수형, 지하상가)│
 37.50  └─────────────────────────────────────────────────────┘
```

## 3. 해저드

계층 빈도 $f_i = 1/T_i - 1/T_{i+1}$ (가장 드문 사건은 $1/T_n$), PR #48 방식 — EAL이 손실초과곡선의 계단
적분과 정확히 같아 해석적 검증이 된다.

### 3.1 하천 홍수 RF (상상 수위 × 실제 지형) — `SYNTHETIC_LOCAL`

- $T \in \{2, 5, 10, 25, 50, 100, 200, 500\}$.
- 본류 수위(표고 기준, 상상): $H_M(T) = 6.0 + 2.2\ln(T/2)$ m → 2년 6.0, 100년 14.6, 500년 18.1.
  (DEM 하안 단구 2–10 m에 맞춰 "100년에 저지가 2~8 m 잠기고 20 m 위 사면은 마른다"가 되도록 잡은 값.
  **실측 아님.** `_note`에 "DEM 분포에 맞춘 상상값" 명시.)
- 지류(중랑천·탄천형) 수위: $H_t(T) = H_M(T) - 1.0$ m, 지류 중심선 500 m 이내에서만.
- 셀 침수심 $d = \max(0,\; H(T)\,e^{-\,x/2000\,\text{m}} - z_{DEM})$, $x$ = 가장 가까운 수체(본류·지류)까지 거리.
  감쇠항은 제내지 배수 묘사(상상).
- 방어: `protection.protect(hazard, 50)` — 저장소 규칙 그대로. 펌프장 3곳 반경 600 m는 PR #44의 제방보호
  로직이 읽는 `pump_stations.csv` 포맷으로.
- 기후 배율(상상): rcp45 2030 ×1.05 / 2050 ×1.10, rcp85 2030 ×1.08 / 2050 ×1.20 — $H$에 곱한다.

### 3.2 하천 홍수 RF (실제) — `GLOBAL_BASELINE`, `DATA_API_COUNTRY`

- 건드리지 않는다. 결과는 0. 그 0이 비교행에 그대로 실려야 한다(§0의 데이터 문제가 화면에 보이게).

### 3.3 태풍 TC

- 세트 A: 실제 `TC_rcp45_KOR_2040` 등 카탈로그 레이어 그대로(`DATA_API_COUNTRY`). 균일 ≈ 50–55 m/s.
- 세트 B(짧은 기록): 관측형 41사건, 빈도 각 1/41 → 100년 손실 요청 시 `RETURN_PERIOD_NOT_RESOLVABLE`.
  기존 관측 TC 세트가 있으면 그것, 없으면 세트 A에서 41사건을 뽑아 재빈도(상상) — 어느 쪽인지 기록.
- 임팩트 함수는 `registry.tc_region_for_country("KOR")`로. 하드코딩 금지.

### 3.4 폭염 HW · 열 사망 HM

- HW: 실제 `HW_*_KOR` 레이어 그대로 → `HAZARD_ONLY`. **주의:** 2026-11-01 현재 디스크 레이어는 TA(일평균)로
  만들어진 구버전. TAMAX 재생성(`heat_korea.py register`)이 끝난 뒤의 레이어를 쓴다. 라벨이 "daily Tmax"인데
  내용이 일평균이면 거짓이므로 구현 전 `catalog.json`의 `source`에 `TAMAX`가 있는지 확인한다.
- HM(레거시 러너): 인구는 OSM 주거 건물 발자국 × 층수 × 1인당 30 m²(상상)로 배분, 65+ 비율은
  옥수·금호 0.26, 잠실 0.18, 압구정·청담 0.16, 성수 0.15(상상). `result_kind = mortality`, indicative 라벨 유지.
- 열섬을 상상으로 입히지 **않는다**(실제 레이어를 쪼개는 셈). 필요하면 별도 `SYNTHETIC_LOCAL` 열 모델로
  라벨을 붙여 나중에.

### 3.5 지진 EQ, 산불 WF

- EQ: 실제 `EQ_observed_KOR` 그대로 → 균일 `Low`.
- WF: 실제 레이어가 이 크롭에서 0이면 0으로 둔다(응봉은 도시 안 작은 숲 — 상상으로 불을 내지 않는다).

### 3.6 내수침수 — 가격 불가

- 엔진에 해저드 없음. 잠실 지하상가·역세권 저점 셀에 **참고용** 도로 침수 문턱 $T + \Delta H$
  (`flood_threshold.pump_head_m`)만 표시. 상태 `NO_HAZARD_DATA`, 금액 null, 뷰어에서 해치.

## 4. 자산

### 4.1 실제 부분
- OSM 건물 발자국 전부(크롭 안 수천~수만 동 — 생성 시 집계해 기록). `building:levels`가 있으면 층수 실제,

## 7. 수용 기준 (테스트로 강제)

1. 자산 1개 EAL = $\sum_i f_i\, v\, \mathrm{MDR}(d_i)$ (rtol 1e-9), 방어 유무 × T 유무 네 조합.
2. 자산별 EAL 합 = 전체 `ImpactCalc.aai_agg` (rtol 1e-9).
3. 커버리지 매트릭스(§2) 각 항목 ≥ 1. 특히 `SYNTHETIC_LOCAL` RF 행 중 손실 > 0과 = 0이 **둘 다** 있고,
   `DATA_API_COUNTRY` RF 행은 전부 0; T > 0.05인 행의 EAL < 같은 자산의 T 없는 EAL.
4. 실제/상상 경계: 상상값이 들어간 모든 행·파일에 `imagined` 플래그; 실제 레이어를 재표집·보정한 흔적 없음.
