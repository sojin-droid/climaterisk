# 한국 사례 전 기능 실행 결과 및 자산운용사 활용 가이드

본 문서는 `climaterisk` 플랫폼(CLIMADA 기반)의 **모든 기능을 한국 포트폴리오로 실제 실행한 결과**와,
자산운용사가 운용자산 기후리스크 시나리오 분석에 활용하기 위한 방법·실행 절차를 정리한다.
모든 수치는 본 저장소에서 재현 가능한 실측 실행값이다 (2026-09-01 실행).

### 핵심 발견 3가지

1. **이 포트폴리오는 전환리스크(NPV 464억)가 물리리스크(NPV 손실 130억)의 3.5배** — 울산 공장형 산업자산은 탄소비용 노출이 지배적.
2. **불확실성의 83%가 취약성 곡선에서 발생** — 해저드 데이터 고도화보다 **국내 손실자료(EM-DAT 등) 기반 취약성 보정이 정밀도 개선의 최우선 순위**라는 정량 근거.
3. 재현주기 한도가 페릴별 이벤트 기록에서 자동 산출됨(태풍 344년 / 지진 57년 / 산불 10년) — 기록이 뒷받침하지 않는 꼬리값을 보고서에 싣는 실수를 구조적으로 차단.

## 3. 자산운용사 선호 Physical Risk 평가 방법과 실행법

### 3.1 지표 매핑 — 금융 언어로

| 플랫폼 산출 | 금융 등가물 | 보고서 용도 |
|---|---|---|
| AAI (기대연간손실) | Expected Loss (EL) | 자산·포트폴리오 기대손실률(AAI/가치) |
| 재현주기 손실곡선 | PML / VaR 유사 (1-in-100 ≈ 99% 연간 VaR) | 꼬리리스크 공시 — 단 **기록 한도 내에서만** |
| 기후변화 델타(%) | 시나리오 민감도 | TCFD/ISSB 시나리오 분석 표 |
| NPV 손실 / %CAPEX | 자산가치 훼손율 | 스트레스 전후 가치 비교 |
| DSCR·등급·CRP(bps) | 신용 스트레스 | 부도/등급하락 채널 |
| Sobol 민감도 | 모델리스크 분해 | "수치의 신뢰도" 근거 제시 |
| 불확실성 p5–p95 | 신뢰구간 | 점추정 단독 보고 방지 |

### 3.2 표준 실행 절차 (일괄 분석)

```
1) 자산 CSV(이름·좌표·가치·통화·업종[·인원]) 준비
2) POST /api/session → PUT 자산·시나리오·페릴 설정
3) POST /run → 폴링 → POST /finance?run_id=…
4) POST /uncertainty (신뢰구간), POST /transition (탄소비용)
5) GET /run/{id}/export?fmt=csv|geojson → 내부 BI/보고서 파이프라인
6) GET /report → 세션 요약 HTML
```

- 배치: 세션당 1포트폴리오 × API 루프. 워커 동시실행 상한은 `max_workers`(config)로 제어.
- **속도 최적화 핵심 = 로컬 해저드 카탈로그.** 해저드를 1회 캐시(`scripts/build_hazard.py cache`)하면
  이후 실행은 Data API 재다운로드 없이 오프라인·재현 가능. 자산이 바뀌어도 해저드는 재사용.
- 시나리오 비교는 RCP2.6/4.5/6.0/8.5 × 앵커연도를 세션 복제로 병렬 산출.

### 3.3 결과 해석 유의사항 (보고서 인용 전 체크리스트)

1. **AAI=0의 세 가지 의미 구분** — 플랫폼이 각 결과에 해석문을 첨부함(footprint 밖 / 임계 미만 / 데이터 없음). 0을 "리스크 없음"으로 옮겨 쓰지 말 것.
2. **홍수는 점자산에 민감** — 격자 침수셀과 좌표가 어긋나면 0. 하천 인접 자산은 폴리곤(footprint)으로 입력 권장.
3. **재현주기 상한 준수** — 각 곡선에 `max_resolvable_return_period` 첨부됨. 산불처럼 기록이 짧은 페릴(10년)에 1-in-100 수치를 요구하지 말 것.
4. **취약성 기본값의 한계** — 기본 곡선은 글로벌 문헌 기반. 불확실성의 83%가 여기서 발생하므로, 국내 보정 전 수치는 ±(p5–p95) 구간과 함께 보고.
5. **보험형 조치의 B/C는 별도 해석** — 위 표 각주 참조.
6. **전환·물리 합산 금지** — 서로 다른 채널(비용 vs 손실). 리포트에는 병렬 표기.
7. 통화·명목 기준: 산출은 입력 통화 명목값. 인플레이션/성장 반영은 후처리 필요.

## 4. 문의 이메일 3개 항목에 대한 답변 초안

### Q1. Open-Meteo API 연동 오류
- **본 저장소(climaterisk)는 Open-Meteo를 사용하지 않음.** 문의에 첨부된
  `github.com/PLANiT-Institute/climate_risk`는 별도 저장소로 보이며, 미팅에서 **어느 도구를
  실행 중인지 먼저 확인** 필요(도구에 따라 답이 다름).
- 본 도구의 외부 연동: CLIMADA Data API·WRI Aqueduct·ECA&D·Copernicus DEM·Geofabrik·NGFS(IIASA)·SEDAC.
  전부 **로컬 카탈로그/드롭인 캐시 구조**라, 방화벽 환경에서는 1회 수동 다운로드 후 완전 오프라인 실행 가능
  (`docs/USER_GUIDE.md` §7·본 문서 §2의 드롭인 경로 참조). 사내 프록시 환경이면 `HTTPS_PROXY` 표준 환경변수로 해결.

### Q2. 기상청 데이터 병용 vs 일반 SSP 시나리오 모델
- 본 도구의 기본 해저드는 CLIMADA Data API의 **RCP 기반 전지구 확률적 이벤트셋**(태풍 합성트랙 등) —
  장점은 시나리오 일관성과 미래 델타 산출(+16.5% 같은).
- 국내 관측(KMA) 병용의 효과는 두 가지: (a) **현재 위험의 국지 정밀도**(관측 격자 해상도),
  (b) **검증·보정 가능성**(모델값을 실측과 대조). 유럽 E-OBS 관측을 표준화 그리드 온램프
  (`hazard_convert`)로 주입해 검증까지 수행한 선례가 본 저장소에 있으며, KMA 격자자료도 동일 경로로 주입 가능.
- 즉 SSP/RCP 전지구셋(미래) + 국내 관측(현재·검증)은 대체가 아니라 **상호보완** 구조.
- "국내 해상도 특화 모델" 문의 → 온램프가 이미 열려 있으므로 KMA 자료 사양(변수·격자·기간) 확정되면 연동 가능.

### Q3. Raw Data의 책임투자보고서 활용
- 유의사항: §3.3 체크리스트 그대로 제공 권장.
- 추가 산출 가능 데이터: 재현주기 곡선(+한도), 연간손실 분포(yearset p50/p90/p99), 해저드 경고밴드,
  불확실성 신뢰구간(p5–p95)·Sobol 민감도, 기후변화 델타, 자산별 GeoJSON(지도 게재용), 적응 조치 B/C.
- 권장 절차: ① 취약성 국내 보정(EM-DAT) → ② 모든 공시 수치에 신뢰구간 병기 → ③ RCP 다중 시나리오 비교
  → ④ 재현주기 한도 내 꼬리값만 공시.
- 다수 자산 일괄 분석: §3.2 절차 + 로컬 카탈로그 캐시. 수백 자산도 세션 분할·워커 병렬로 처리 가능하며,
  해저드 캐시 후에는 자산 수에 거의 선형.

## 5. 재현 방법

```bash
./run.command                          # 앱 기동 (backend 8099 / frontend 5174)
# 세션 생성·자산 입력 후 Results → Run analysis
# 또는 API: 본 문서 §3.2 절차
```
한국 해저드 4종은 `data/hazard_db/`에 캐시되어 있어 오프라인 재현 가능.
