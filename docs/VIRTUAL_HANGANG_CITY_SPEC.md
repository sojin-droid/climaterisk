# 가상 한강도시 (Virtual Hangang City) — 디지털 트윈 설계 명세

> **상태:** 설계 명세 v0.1 (2026-11-01). 구현 전. 구현 주체: 자율 에이전트(Hermes)가 Mac mini에서
> 이 문서와 저장소만 보고 만든다. 사람이 읽고 수정하는 문서이기도 하다.
>
> **한 줄 요약:** 서울의 공간 구조를 **본뜬**(복제가 아닌) 가상 도시를 시드 고정으로 생성하고,
> 이 저장소의 CLIMADA 엔진이 가격을 매길 수 있는 **모든 위험 경로가 최소 한 번씩 드러나도록**
> 지형·해저드·자산을 배치한 뒤, 결과를 3D로 본다. 모든 수치는 `_note`가 붙은 **가정값**이다.

## 0. 원칙 (어기면 구현이 틀린 것)

1. **서울이 아니다.** 서울의 *구조*(강·지류·구릉·저지대·도심·공단·하구)를 본뜰 뿐, 실제 건물·필지·
   인구·주소 데이터는 **한 점도 쓰지 않는다.** 결과를 서울 어느 동네의 위험으로 읽어서는 안 되며,
   문서·UI·파일명 어디에도 실제 자치구 이름을 **그 구역의 이름으로** 붙이지 않는다
   (설명에 "○○형"이라고 모사 대상을 적는 것만 허용).
2. **엔진은 건드리지 않는다.** 가격 산정은 전부 `climaterisk_worker.physical_risk.engine.calculate`
   를 통과한다(PR #48 `scripts/synthetic_city.py`와 같은 규율). 새 임팩트 함수를 만들지 않는다.
   발표 곡선(JRC 아시아 6개 섹터, Eberenz WP4)만 쓴다.
3. **모든 가정값은 한 파일에.** `assets/libraries/virtual_hangang_city_spec.json` — 숫자를 바꾸려면
   코드가 아니라 여기를 바꾼다. 모든 숫자 옆에 `_note`로 "가정"임과 근거(있으면)를 적는다.
4. **없는 건 없다고 낸다.** 임팩트 함수가 없으면 금액은 null(0이 아님), 재현기간을 해석할 수 없으면
   `RETURN_PERIOD_NOT_RESOLVABLE`. 디지털 트윈은 이 "없음"도 **보여 줘야** 한다.
5. **세 해상도를 구분한다.** 원 해상도(가상이므로 생성 격자) / 저장 해상도 / 계산 해상도를 메타데이터에
   따로 적는다. 이 도시는 전부 100 m 격자에서 생성·저장·계산하므로 셋이 같지만, 같다는 사실도 적는다.
6. **시드 고정, 재현 가능.** `numpy.random.default_rng(seed)`. 같은 spec → 바이트 동일 출력.

## 1. 왜 이 공간인가 — "다채롭게 드러나려면"

엔진이 지금 낼 수 있는 결과의 종류를 전부 나열하고, 그 각각이 **어느 구역에서 나타나야 하는지**
먼저 정한다. 아래 표가 설계의 요구사항이자 §8의 수용 기준이다.

| 엔진 경로 | 상태/결과 | 반드시 나타나는 구역 |
|---|---|---|
| 하천 홍수 RF, JRC 곡선, `FULL` | 큰 손실 | 저지대 주거(§2 Z4), 강변 공단(Z6) |
| RF `FULL`이지만 손실 ≈ 0 | 고지대 | 구릉 주거(Z3), 도심 고지(Z2 일부) |
| RF **방어 기준** (국가 기본 P년, 월류 규칙) | `flood_protection_return_period_years` | 전역 — P 이하 사건이 사라지는 것이 보여야 |
| RF **펌프장 제방보호 셀** | `levee_protected = true`, 펌프 계획빈도 기록 | 강변 저지대(Z4·Z6) 펌프장 반경 |
| 해안 홍수 CF, 같은 JRC 곡선, `haz_type CF` | 방조제 100년 · 항만 50년 기준 → 200·500년에만 손실 | 하구·해안(Z7) |
| **무피해 문턱** T (PR #49) | T가 큰 자산은 같은 침수심에 손실 0 | 지하 연계 상업(Z2), 반지하 주거(Z4), 차수판 설치 공단(Z6) |
| 태풍 TC, Eberenz WP4 id 9 | 해안→내륙 감쇠 | Z7 > Z6 > Z2 > Z3 |
| TC **짧은 기록** 세트 | `RETURN_PERIOD_NOT_RESOLVABLE` (100년 손실 null) | 전역, 두 번째 TC 세트로 |
| 폭염 HW (TAMAX p95) | `HAZARD_ONLY`, 금액 null, 강도만 | 도심(Z2) 열섬 최고, 산록(Z3)·강변 최저 |

| 산불 WF (레거시 러너) | 산림 접경에서만 | 산림(Z8) 접경 Z3 |
| 지진 EQ (레거시 러너) | 전역 낮고 균일 → `Low` | 전역 |
| 위험 등급 Low / Medium / High | 세 등급 모두 존재 | — |
| JRC 6개 섹터 | residential / commercial / industrial / transport / infrastructure / agriculture 전부 | Z1~Z7 + 도로·지하철 + 농지(Z5) |
| 포트폴리오 손실 곡선 (사건 합, 비가산) | 재현기간별 | 전역 |
| 네트워크 단절 지표 (변전소·병원 도달 불가 주거 가치) | USD/yr 지표 | Z4 주거 — 펌프장 실패 시 |
| 기후 배율 (present→future) | RF·CF·TC·HW 각각 | 시나리오 3 × 연도 2 |
| **가격 불가 해저드** | 내수침수(도로 침수) — 엔진에 해저드 없음 | 도심 저점(Z2 "역세권 저점") — **참고치만**, 금액 없음 |

## 2. 공간 설계

### 2.1 범위와 격자

- 영역 **24 km (동서) × 18 km (남북)**, 셀 **100 m** → 240 × 180 = 43,200 셀. 서울(약 35 × 30 km)을
  1/2 축척으로 압축한 크기. 원점 위경도는 가상(`origin_lat 37.0, origin_lon 127.0` — PR #48과 동일,
  실제 서울 좌표가 아님).
- 좌표 변환은 PR #48 `_to_latlon` 재사용(위도 1° = 111,320 m, 경도는 cos(lat) 보정).

### 2.3 지형

$$z(x,y) = z_{zone} + s_{zone}\, d_{river}(x,y) + h_{hill}(x,y) + \varepsilon,\qquad \varepsilon\sim N(0,\sigma^2)$$

- `d_river`: 본류·지류 중 가장 가까운 수체까지 거리(m). 구역별 기준고 `z_zone`과 경사 `s_zone`:
  Z4 0.5 m·0.001, Z6 1.5 m·0.001, Z1/Z2 4 m·0.004, Z3 20 m + 구릉, Z7 폴더 **−0.5 m**(방조제 뒤 저지).
- `h_hill`: Z3·Z8에 가우시안 언덕 2~3개(정점 150–300 m). Z2에 작은 언덕 1개(종로 북쪽 고지형).
- `σ` = 0.3 m. 바닥은 Z7 폴더 제외 0 m에서 자름.

## 3. 해저드 설계 (구역별로 무엇이 드러나는가)

모든 해저드는 **재현기간별 계층 사건**으로 만든다(PR #48 방식): 사건 i의 빈도
$f_i = 1/T_i - 1/T_{i+1}$, 가장 드문 사건은 $1/T_n$. 그래야 CLIMADA의 EAL이 손실초과곡선의
계단 적분과 정확히 같아 해석적 검증이 된다.

### 3.1 하천 홍수 RF — `haz_type "RF"`, 단위 m

- 재현기간 $T \in \{2, 5, 10, 25, 50, 100, 200, 500\}$.
- 수위: 본류 $h_M(T) = 0.3 + 0.9\ln(T/2)$, 지류 $h_A(T) = 0.2 + 0.7\ln(T/2)$ (m, 가정). 셀의 수위는
  가장 가까운 수체의 값에 거리 감쇠 $e^{-d/1500\,\text{m}}$를 곱한다(배수 불량 저지대 묘사).
- 침수심 $d(T) = \max(0, h(T) - z)$.
- **방어:** `physical_risk_config.json → flood_protection.presumed_defended_return_period_years`
  (현재 2년; 이 도시 실행에서는 spec의 `protection_rp` = **50**을 권장값으로 넘겨 월류 규칙이 눈에
  띄게 하라). `protection.protect` 그대로 사용.
- **펌프장 제방보호:** 펌프장 12곳에 반경 600 m, 계획빈도 10/20/30년. 엔진의 펌프장 보호 로직
  (PR #44 `d1523be`)이 읽는 포맷으로 `pump_stations.csv`를 낸다 → 해당 셀의 설계 재현기간이 상향.
- 기후 시나리오: 수위에 배율 — rcp45: 2030 ×1.05, 2050 ×1.10; rcp85: 2030 ×1.08, 2050 ×1.20
  (전부 가정, `_note`에 "가정 — 문헌 치환 필요").

### 3.2 해안 홍수 CF — `haz_type "CF"`, 단위 m (Z7만)

- 해일고 $S(T) = 1.0 + 1.2\ln(T/2)$ (m above datum, 가정). 해안선에서 내륙으로 $e^{-d/800\,\text{m}}$ 감쇠.
- 침수심 $d = \max(0, S(T) - z)$ — Z7 폴더는 z < 0이라 **방어 없으면 2년에도 침수** (실제 간척지 양상).
- **방어 기준:** 방조제 뒤 폴더 **100년**, 항만 **50년**(저장소 config의 `coastal_protection` 자산별
  표준 — PR #44의 항만 50 / 방조제 100 규칙을 그대로 사용). → 200·500년 사건에서만 손실이 나타남.
- 기후 배율: 해수면 상승 가정 rcp45 2050 +0.25 m, rcp85 2050 +0.40 m를 $S$에 더함(가정).

### 3.3 태풍 TC — `haz_type "TC"`, 단위 m/s

- 세트 A(가격용): $T \in \{5,10,25,50,100,200\}$, 해안 풍속 $v(T) = 28 + 9\ln(T/5)$ m/s, 내륙 감쇠
  $v \cdot (1 - 0.15\, d_{coast}/24\,\text{km})$, 구릉 노출 +5 %.
- 세트 B(**짧은 기록**): 관측형 41년 — 사건 41개, 빈도 전부 1/41 → 100년 손실 요청 시
  `RETURN_PERIOD_NOT_RESOLVABLE`이 **나와야 한다**(ceiling 41년). 이 경로를 보여 주는 것이 목적.
- 임팩트 함수: `registry.tc_region_for_country("KOR")` → id 9 WP4. 하드코딩 금지.
- 기후 배율: 풍속 rcp85 2050 ×1.06 (가정).

### 3.4 폭염 HW / 열 사망 HM — 단위 °C

- 여름철 **일최고기온 p95** 격자(HW, S7 Option C와 동일 정의):
  $$\text{Tmax}_{p95} = 33.0 + \Delta_{UHI}(\rho_{build}) - 1.5\,g_{green} - 1.0\,e^{-d_{river}/500} + \varepsilon$$
  $\Delta_{UHI}$ = 건폐·고층 밀도에 비례 0~+3.5 °C(Z1·Z2 최대), $g_{green}$ 산림 인접도 0~1.
  → Z2 ≈ 36.5, Z3 ≈ 32.5, 강변 ≈ 33.
- HW는 모델 엔진에서 **`HAZARD_ONLY`** — 금액 null, 강도만. 이것이 그대로 표에 보여야 한다.
- HM(레거시 러너 `heat_mortality`): 셀별 인구·65+ 비율 필요. 구역별 인구밀도(명/ha) Z1 150, Z2 120,
  Z3 250, Z4 300, Z6 20, Z7 80, Z5 5; 65+ 비율 Z3 0.28, Z4 0.20, Z1 0.12, 기타 0.17 (전부 가정).
  결과는 `result_kind = mortality`, 커스텀 곡선이므로 **indicative** 라벨 유지.
- 기후 배율: Tmax에 rcp45 2050 +1.2 °C, rcp85 2050 +2.0 °C (가정).

### 3.5 산불 WF · 지진 EQ (레거시 러너, 드러내기용)

- WF: 산림(Z8) 경계로부터 300 m 이내 Z3 셀에만 강도(FWI 유사 지표) 부여, 그 밖은 0. 레거시
  `wildfire` 러너가 읽는 포맷으로 저장. 목적: "접경에서만 나타나는 위험" 시각화.
- EQ: 전역 PGA 0.05–0.08 g 균일 + 약한 노이즈 → 전 자산 `Low`. 목적: "있지만 낮은 위험"의 표현.

### 3.6 가격 불가 — 내수침수(도로 침수)

- 엔진에 해저드가 없다. Z2 저점 셀 군(역세권 저점형)에 **참고용** 도로 침수 문턱
  $T + \Delta H$만 표시(PR #49 `pump_head_m`). 금액 **없음**, 상태 `NO_HAZARD_DATA` 그대로.
  디지털 트윈은 이 셀을 "평가 불가" 해치로 그린다.

## 4. 자산 설계

### 4.1 수량과 배치

| 종류 | 수량(가정) | 배치 규칙 |

### 4.2 자산 속성 (엔진 입력 + 3D 표현)

| 속성 | 엔진 필드 | 생성 규칙(가정) |
|---|---|---|
| 가치 | `asset_value_usd` | 연면적 × 용도별 m²당 재조달가(상업 2,600 / 주거 2,100 / 공업 1,500 / 인프라 3,000 USD·m⁻², 2026 신축단가 수준 가정) × lognormal(σ 0.3) |

| 층수·높이 | (3D 전용) `floors`, `height_m` | Z1 15–40층, Z2 5–15, Z3 2–5, Z4 2–6(반지하 포함), Z6 1–3(대형 평면), Z7 1–4 |

| 1F 바닥 높이 | `first_floor_m` | Z1 0.3, Z2 0.4, Z3 0.6, Z4 **−0.8(반지하)**~0.3, Z6 0.9(하역장), Z7 0.5 |
| 문턱·차수판·차수벽 | `sill_m`, `board_status`, `board_m`, `wall_status`, `wall_m` | 차수판 설치됨: Z6 50 %, Z4 20 %, Z1 30 %; 계획/권고: 15 %; 차수벽: Z6 10 % (높이 0.8–1.2) |

| 인구 | (HM 전용) | 구역 인구밀도 × 셀 면적, 주거 건물에 배분 |

## 8. 수용 기준 (테스트로 강제)

1. **해석적 일치:** 자산 1개를 골라 EAL = $\sum_i f_i\, v\, \mathrm{MDR}(d_i)$ (rtol 1e-9), 방어 유무·
   T 유무 네 조합 모두. (PR #48·#49 테스트와 같은 형식)
2. **ImpactCalc 항등식:** 자산별 엔진 EAL 합 = 전체 `ImpactCalc.aai_agg` (rtol 1e-9), 해저드별.
3. **커버리지 매트릭스:** `summary.json`의 (해저드 × 상태) 표에 다음이 **모두 ≥ 1**:
   RF `FULL`, CF `FULL`, TC `FULL`, TC-B `RETURN_PERIOD_NOT_RESOLVABLE`, HW `HAZARD_ONLY`,
   내수침수 `NO_HAZARD_DATA`; 등급 Low·Medium·High 각 ≥ 1; JRC 6개 섹터 각 ≥ 1;
   `levee_protected = true` ≥ 1; `flood_zero_damage_threshold_m` > 0.05인 행 ≥ 1이고 그 행의
   EAL < 같은 자산의 T 없는 EAL.
4. **원칙 1 검사:** 산출물 어디에도 실제 자치구·동 이름이 **구역명으로** 등장하지 않는다(허용 목록:
   "○○형" 설명 문자열만).
5. **재현성:** 같은 spec·시드 → `assets.parquet` 해시 동일.
6. **없음은 null:** HW 행의 `eal_usd`, `potential_loss_usd`, `risk_level` 전부 null.
7. **세 해상도 기록:** `spec_used.json`에 source/stored/calculation 해상도 100 m 명시.
