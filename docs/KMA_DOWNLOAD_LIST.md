# 기상청 남한상세 1 km 다운로드 목록 (기후변화 상황지도)

다운로드는 **로그인 필수**(climate.go.kr/atlas/auth/login → 회원가입 가능).
다운로드 버튼을 누르면 소속·활용분야·사용목적 설문 창이 뜨고, 제출 후 파일이 내려온다.
포털 URL: https://climate.go.kr/atlas/ana/cdd — 왼쪽 필터에서 **남한상세 › 격자 › 기후요소**를 체크하고
카드 안의 요소 라디오에서 **평균기온**을 고른다. 아래 표의 `ds`/`file`은 다운로드 버튼의
`data-dataset-id` / `data-file-id` 값이라 행을 찾는 데 쓸 수 있다.

받은 파일(tar.gz 그대로, 압축 해제하지 말 것)은 `~/climada/data/kma/` 에 넣는다. 그 뒤:

```bash
./.climada-env/bin/python scripts/heat_korea.py files      # 체크 표시 확인
./.climada-env/bin/python scripts/heat_korea.py register   # 카탈로그 등록
./.climada-env/bin/python scripts/heat_korea.py run        # 데모 포트폴리오 실행
```

## 실제로 받은 것 (2026-09-11 확인)

| 데이터셋 | 창 | 형식 | 파일명 |
|---|---|---|---|
| MK-PRISM **v3.1** 남한상세 격자 (관측 기반) | 2000–2019 | **nc** (5.2 GB) | `MKPRISM_MKPRISMv31_TA_gridraw_daily_2000_2019_nc.tar.gz` |
| SSP2-4.5 남한상세 격자 | 2021–2030 | **asc** (440 MB) | `AR6_SSP245_5ENSMN_skorea_TA_gridraw_daily_2021_2030_asc.tar.gz` |
| SSP5-8.5 남한상세 격자 | 2021–2030 | **asc** (440 MB) | `AR6_SSP585_5ENSMN_skorea_TA_gridraw_daily_2021_2030_asc.tar.gz` |

포털이 실제로 내주는 것은 위 표 그대로이고, 예상과 세 군데 달랐다. 로더(`kma_scenario.py`)는
이제 셋 다 읽는다.

1. **AR6 남한상세는 `nc`가 없다.** 시나리오 카드의 파일형식은 `asc`뿐이다. 헤더 없는 ASCII로,
   **1줄 = 하루**, 줄마다 751×601 = 451,351개 값이 위도 오름차순 row-major로 들어 있다
   (윤년은 366줄, SSP2-4.5 2024로 확인). NetCDF 마스크와 교차검증해 방향을 확정했다
   (일치 98.2%, 위도 뒤집으면 85.4%).
2. **파일명에 `skorea` 토큰이 없는 산출물이 있다.** MK-PRISM은 `MKPRISM_MKPRISMv31_TA_…`,
   AR6은 `AR6_SSP585_5ENSMN_skorea_TA_…`. 또 아카이브 안의 멤버는 **연도 1개씩**이다
   (`…_daily_2000.nc`), 파일명의 `2000_2019`는 아카이브에만 붙는다.
3. **관측과 미래의 격자 해상도가 다르다.** MK-PRISM v3.1은 **1201×1501 @ 0.005°(~500 m)**,
   AR6 시나리오는 601×751 @ 0.01°(~1 km). 두 격자는 짝수 노드를 공유하므로 v3.1을
   `[::2, ::2]`로 **서브샘플링**해 0.01° 노드에 정확히 맞춘다. 블록평균을 쓰면 셀 중심이
   0.0025° 어긋나 `heat_mortality`의 기준밴드 상속 좌표 검사가 거부한다.

### 디스크 주의

ASCII 한 해가 **1.3 GB**, 시나리오당 10년이면 13 GB다. 그래서 `extract_archives()`는
`_asc.tar.gz`를 **건드리지 않고**, 로더가 tar를 스트림으로 열어 6–9월 122줄만 파싱하고 나머지는
버린다. 디스크에 남는 것은 없다. NetCDF(MK-PRISM)만 압축을 푼다(20개 × 266 MB ≈ 5.3 GB).

## 용량 계획

파일 크기는 로그인 전에는 보이지 않는다. 1 km 격자 × 10년 일자료는 **비압축 약 6.6 GB/파일**
(751×601×3,653일×4바이트)이고 NetCDF 압축이 걸려 있으면 1–3 GB로 줄어든다. 현재 디스크 여유는
**24 GB**이므로 17개 파일을 한 번에 두는 것은 불가능하다. 권장 운영:

1. 파일을 **한두 개씩** 받아 `~/climada/data/kma/`에 두고 `register`를 돈다.
2. `register`가 끝난 원본 tar.gz/nc는 지우거나 iCloud Drive
   (`~/Library/Mobile Documents/com~apple~CloudDocs/climada-kma/`)로 옮긴다. 카탈로그에 남는
   HDF5는 5 km 블록 평균 기준 수십 MB 수준이다.
3. `register`는 창(window) 단위로 독립이라 파일이 도착하는 순서대로 나눠 돌려도 된다.

## 주의 — 앙상블 평균

SSP 파일은 5개 지역기후모델의 **일별 앙상블 평균(5ENSMN)** 하나만 제공된다. 모델별 일자료를
날마다 평균하면 각 모델의 열파가 서로 상쇄되어 극값이 눌린다. 따라서 미래 초과 온도일수(degree-days)는
**하한 추정치**로 읽어야 한다. 과거 MK-PRISM은 관측 기반이라 이 문제가 없다. 카탈로그 `source`
문자열에 "ensemble-mean daily fields: extremes damped"로 표기된다.
