# 시각 보드 (Visual Board) — 설계 결정

작성 2026-11-10. 사용자 결정 반영(추천안 채택, 강남 사례는 "미검증" 배지로 공개).

## 1. 두 층
| 층 | 범위 | 해상도 | 비고 |
|---|---|---|---|
| 전국 기본 평가 | 전국 자산·시군구 | 재해 자료 해상도 그대로 (CLIMADA Data API 150″ ≈ 4.6 km, KMA 0.05° ≈ 5 km) | EIOPA CLIMADA-App과 비교되는 층 |
| 사례 트윈 | 영향이 두드러지는 대상지 | 대상지별 (강남 10 m) | 별도 페이지, 전국 결과와 합산·비교 불가 |

## 2. 지도 (전국 층)
- **B (기본)**: 재해 격자 한 칸 ∩ 시군구 경계 = "조각". 조각은 그 격자 값으로 칠한다. **평균하지 않는다.**
  경계에 걸린 격자는 조각 여러 개로 나뉘고 값은 같다(소속 시군구만 다름).
- **재현주기 선택**: CLIMADA `Hazard.local_exceedance_intensity` (method `extrapolate_constant`: 가장 잦은 사건보다
  더 잦은 재현주기는 0). 상한은 `physical._resolvable_return_periods`와 같은 규칙(사건 기록 길이의 ½); 상한을 넘는
  재현주기는 계산하지 않고 "계산 불가"로 표시한다(대체값 없음).
- **지점 조회**: 지점이 들어간 조각의 값을 돌려준다. 자산 평가가 "가장 가까운 재해 격자"를 읽는 것과 같은 값이어야
  한다(테스트로 고정).
- **시군구 요약**: 조각 수, 최소, 최대만. 평균은 내지 않는다.
- **null ≠ 0**: 값이 없는 곳(자료 범위 밖)은 null, 계산된 0은 0.
- **C (선택, 기본 꺼짐)**: LitPop 노출 가중. 재해는 격자 값 그대로, LitPop 1 km 점은 가장 가까운 재해 격자 값을 받고
  노출 × 피해율로 손실을 계산, 조각·시군구 값은 **합계**. 화면 문구(고정):
  > 노출 가중(LitPop) 켜짐 — 재해 값은 4.6 km 격자 그대로 사용합니다. 건물과 인구가 많은 곳의 영향을 1 km 단위 노출로
  > 가중해 손실을 계산합니다. LitPop은 공개 모델 추정값(야간 조명 × 인구)입니다.
- 시군구 **대표점 방식은 폐기**(`docs/municipality-physical-risk.md`의 대표점 문구는 B 도입과 함께 교체).

## 3. 화면 (새 탭 "시각 보드", 기존 Map 탭은 자산 입력용으로 유지)
전국 → 시군구 → 지점·자산 → 사례 트윈. 트윈은 줌으로 자동 전환하지 않고 사례 핀 클릭 + 전환 안내를 거친다.
- 해상도 배지, 사용 등급(S/I/D) 배지 + 이유 한 줄(SCOPE.md), 해상도 사다리, "격자 한 칸" 크기 표시.
- 재해는 면 색(단색 계열 순차 팔레트), 노출은 속이 빈 점 크기 — 색 체계 분리. 색·구간은 [BOARD_COLORS_KO.md](BOARD_COLORS_KO.md) 한 곳에서 정한다. 격자 조각은 각진 경계(보간 금지).
- 한 번에 재해 하나. 한국어 우선, 영어 병기.
- 사례 트윈 페이지(강남 템플릿, 8칸): 헤더(+ **미검증** 배지: 모델 CSI 0.29 < 단순 규칙 0.57) / 전국 격자 vs 10 m 비교 /
  문턱 전·후 지도(% 변화만, 금액 숨김, 평가 243동 채움·제외 637동 외곽선) / 검증 패널 / 모델 상태 민감도 /
  말할 수 있는 것·없는 것 / 가정 목록(개수 항상 표시) / 다음에 필요한 자료.

## 4. 만들지 않을 것
종합 위험 점수, 재해 합산 색칠, 시군구 종합 순위, 3D 건물, 트윈 실시간 재계산, 줌 자동 전환, 트윈 금액,
검증 전 트윈 결과의 전국 지도 반영.

## 5. 순서
1. 백엔드 핵심: 재현주기 강도, 조각 생성, 지점 조회, 시군구 요약 (하천홍수 과거 KOR 1980–2000부터)
2. API + 보드 탭의 전국 조각 지도·재현주기·클릭 조회·배지
3. null/0 범례, 해상도 사다리 · 4. 시군구 패널 + 대표점 문구 교체 · 5. 지점 자산 입력 + 엑셀
6. 강남 트윈 페이지(계산된 결과 읽기 전용) · 7. LitPop 켜기 · 8. 나머지 재해, 가뭄(팜맵)

## 6. 미래 변화 지도 (하천 홍수·태풍)
- **변화 층** = 같은 격자의 두 층에서 `미래 ÷ 기준` 배율을 낸 층(`visual_board.json`의 `change_layers`). 조각이 두 층에서
  정확히 같아야 하며(격자·시군구·모양), 다르면 빌드가 실패한다. 재현주기는 두 층이 모두 계산 가능한 것만 남긴다
  (교집합). 색은 `board_palettes.json`의 `change` 한 가지 발산 팔레트(위험이 커지는 쪽이 자홍).
- **기준이 0인 곳**: 기준 0이고 미래 > 0이면 배율을 정의할 수 없어 `status = base_zero`("기준 0 · 배율 없음", 흰 바탕 + 회색
  테두리). 둘 다 0이면 `both_zero`("0 · 영향 없음"), 한쪽이 자료 없음이면 `null`. 무한대·임의 보정값은 쓰지 않는다.
- **같은 조건 기준선(like-for-like)**
  - 하천 홍수: 기준과 미래가 **같은 RCP**의 두 기간(2010–2030 대 2030–2050). 재분석 강제 "historical" 세트와는 비교하지 않는다
    (모형 사슬이 달라 변화가 아닌 차이가 섞임; `physical.py` 주석).
  - 태풍: 기준은 **과거(historical) 합성 경로 10개 집합(1980–2020)**, 미래는 같은 합성 경로 수의 **2040년**
    RCP4.5·6.0·8.5 집합. 기준이 관측 기간 평균이고 미래가 2040년 한 시점이라 기간이 같지 않다. 풍속(`wind_ms`)만 다루며
    침수·강우는 제외.
- **사용 등급**: 변화 층은 시나리오 차이(같은 모형 사슬)라 절대값 오차 일부가 상쇄되지만, 등급은 두 층 중 낮은 쪽(I)을 따른다.
- **재현주기 보조 확인(sub check, 필수)**: 모든 재현주기 층은 주 방법(CLIMADA `local_exceedance_intensity`) 하나만 결과로
  쓰고, 보조로 경험적 계단 규칙(초과빈도 ≥ 1/T인 사건 중 최대 강도, 보간 없음)을 같은 사건 집합에서 계산해
  `meta.check`에 기록한다. 기간별로 두 값이 `rel_tol`(0.25) 넘게 다른 격자 비율을 `disagree_share_by_period`에 담고,
  어느 기간이든 `warn_share`(0.10)를 넘으면 `warning=true`와 빌드 로그 경고를 남긴다. 진단용이며 두 번째 결과로
  지도에 보이지 않고 주 결과를 바꾸지 않는다.
- 빌드: `board_layer.py --fetch --all`(온라인, 없는 hazard만 한 번에 하나씩) 후 `--all`(오프라인 빌드, 층 전부와 변화 층).

## 7. 전국 2단계 층 (해안 침수·산불·폭염일수·폭염 건강)

### 7.1 해안 침수 `coastal_flood_hist_kor` · `coastal_flood_rcp85_2030_kor` · 변화 `coastal_flood_change_rcp85_kor` (등급 S)
- **자료**: WRI Aqueduct Floods v2 `inuncoast`(30″ ≈ 0.9 km, 지반침하 반영). `<DATA_ROOT>/cache/aqueduct/*.npz`에 이미 있는
  재현주기별 침수 깊이 지도 9장(2·5·…·1000년)만 읽는다(오프라인). 사건 집합이 아니라 **재현주기마다 한 장**이다.
- **주 방법**: 지도 9장을 사건 9개(빈도 `1/T_i − 1/T_{i+1}`, 가장 긴 기간은 `1/T`)로 만든 CLIMADA 하자드에 다른 재현주기 층과
  같은 `board.rp_intensity`를 쓴다. 지도가 겹쳐 쌓여(깊이가 기간에 따라 줄지 않음) 사건 i의 초과빈도가 `1/T_i`이므로 지도 값이
  그대로 나온다. 기록 길이는 1000년이라 절반 규칙으로 **500년까지** 쓴다(2–500, 8개).
- **보조 확인(진단 전용, `meta.check`)**: 경험적 계단 규칙(`rp_intensity_check`), 원본 지도의 **재현주기 단조성**(깊이가 기간이
  길수록 줄면 위반), 원본 지도와 주 결과의 일치(`raw_map_vs_main`). 경고 기준은 다른 층과 같은 `rp_check`.
- **격자**: 캐시 상자(과거 125.5–129.5°E, 2030 층 126–130°E, 둘 다 33–38.5°N)의 합집합에서 어느 층이든 한 번이라도
  물에 잠기는 칸만 조각으로 만든다. 두 층의 조각이 같아 변화 층이 만들어진다. **한 층의 상자 밖은 null**(0 아님)이다.
  캐시는 "침수 없음"과 "자료 없음"을 구분하지 못하므로(둘 다 0) 상자 안의 0은 침수 없음으로 읽는다.
  울릉·독도·백령도 등은 상자 밖이다.
- **변화 층**: 2030 층 ÷ 과거. 기준은 Aqueduct 역사 해수면, 미래는 RCP8.5 2030의 해수면 상승 50번째 백분위이며 같은
  모형 사슬·같은 격자다. 즉 **해수면 상승 시나리오 차이**이지 같은 RCP 두 기간 비교가 아니다. 방어시설은 어느 쪽에도 없다.
- **사용 등급 S**: 방어시설(방조제·호안) 미반영이라 매립지는 2년 빈도에도 수 m 침수가 나온다(docs/SCOPE.md coastal_flood 행).

### 7.2 산불 `wildfire_hist_kor` (등급 S)
- CLIMADA Data API `wildfire_KOR_150arcsec_historical_2001_2020`(시즌 20개, 밝기온도 K)를 로컬 캐시에서 읽어 일반 재현주기
  층으로 만든다. 기록이 20년이라 상한이 10년이어서 **2·5·10년**만 남는다. 주 방법과 보조 확인은 다른 재현주기 층과 같다.
  시즌 20개뿐이라 2년 값은 두 방법이 갈릴 수 있다(기록은 `meta.check`).

### 7.3 폭염일수 `heat_days_kor` (등급 S) — `scripts/heat_days_board.py`, `assets/libraries/heat_days.json`
- **정의**: 일 최고기온(TAMAX) 33 °C 이상인 날, 5–9월, 연평균 일수. 기상청 폭염 기준 33 °C를 **기온**에 적용(체감온도 아님).
  KMA 남한상세 0.01° 격자를 기존 폭염 하자드와 똑같이 0.05° 블록 평균(`kma_scenario._block_mean`)한 칸이 조각의 기준이다.
- **주 방법(델타법)**: 현재 = 관측(MK-PRISM v3.1) 2000–2019. 미래 = 관측 일자료 + 칸·월별 모델 변화량
  (모델 2051–2060 월평균 − 모델 2021–2030 월평균), 그 날들을 같은 방식으로 센 값. 키: `obs_2000_2019`,
  `ssp245_2051_2060_delta`, `ssp585_2051_2060_delta`(일/년), `ssp245_ratio`, `ssp585_ratio`(미래 ÷ 관측, `board.change_values`로
  `base_zero`·`both_zero` 표시). 델타 라벨은 "관측 + 모델 30년 변화량"이다.
- **왜 델타인가**: AR6 `5ENSMN` 일자료는 모형 5개를 날마다 평균한 **앙상블 평균**이라 일 변동폭이 눌린다(7월 일 표준편차
  3.2→2.6 °C). 또 여름 평균이 관측(MK-PRISM)보다 높게 놓여 있다(2021–2030 7월 약 +1.7 °C). 그 일자료를 직접 세면 두 효과가
  반대로 작용해 관측 폭염일수와 크게 어긋난다(실측: 전국 칸 평균이 관측의 +53 % SSP2-4.5, +69 % SSP5-8.5). 월평균의 변화량은
  수준 차이를 상쇄하고, 관측의 일·연 변동은 그대로 남는다.
- **보조 확인(진단 전용, `meta.check`)**: (1) 모델 2021–2030을 직접 센 값 대 관측 2000–2019(`bias_check`; 위 실측대로 크게 어긋나 경고가 켜지며
  이것이 델타법을 주 방법으로 쓰는 이유다. 월별 수준 차이·변동폭 비는 `climate_bias`), (2) 모델 직접 비(2051–2060 ÷ 2021–2030) 대 델타법 비. 두 비는 기준
  기간이 달라(관측 대 모델 2021–2030) 같은 값이 아니며 비교용으로만 기록한다.
- 관측 칸 4,691개 중 모델 땅 마스크와 겹치는 4,312칸만 미래·배율 값이 있고 나머지는 **null**이다.

### 7.4 폭염 건강 `heat_health_kor` (등급 I, 비율만) — `scripts/heat_health_board.py`, `assets/libraries/heat_health.json`
- **하자드·취약성**: `HM_historical_KOR_2020.hdf5`(초과도일, 2000–2019 시즌 20개, 0.05°)와 저장소의 연령대별(<65, 65+) 열 사망 함수
  (`heat_mortality.build_impact_functions`, KOSIS 2024 기저 사망률). 과학은 새로 만들지 않고 `physical._run_heat_mortality`와
  같은 노출 행(조각 × 연령대)을 쓴다.
- **노출**: WorldPop 2024 1 km 연령별 인구(CC BY 4.0). 1 km 픽셀 중심이 들어 있는 조각에 **합산**한다(인구 합이며 하자드 평균이
  아님). 2024년 인구·연령 구조를 2000–2019 모든 시즌에 그대로 쓴다. 인구가 0인 조각의 비율은 null.
- **키**: `rate_per_100k`(연평균 2000–2019), `rate_2018`(2018 시즌), 둘 다 `heat_deaths_per_100k`. 노출 합 `pop_total`,
  `pop_65plus`(명). **절대 사망자 수는 지도 키가 아니다**(등급 S).
- **보조 확인(진단 전용)**: 전국 2018 모형 비율을 발표된 2018 초과사망률(Choi 외 2024, 8.3/10만 인년)과 비교(`warn_ratio`
  [0.5, 2.0], 비율과 경고를 `meta.check`에 기록), WorldPop 전국 65+ 비중을 KOSIS 비중(0.203)과 ±3 %p로 비교(기록만). 두 값은
  같은 양이 아니어서(모형: 5–9월 노출 시즌의 열 기인 사망, 기준: 2018 폭염의 초과사망 인년) 타당성 점검이지 보정이 아니다.
- **미래 층 없음**: 미래 TA는 2021–2030 앙상블 평균(극값 눌림)뿐이라 과거와 같은 기준이 아니다.
