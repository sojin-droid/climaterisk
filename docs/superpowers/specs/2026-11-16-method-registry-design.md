# 방법 등록표 설계 (2026-11-16)

## 왜 하나

분석을 여러 번 나눠 하다 보니 같은 재해를 화면마다 다른 방법으로 계산하고 있다. 아래는 2026-11-16 코드와 디스크를 직접 확인한 결과다.

- **하천 홍수:** 자산 평가는 홍수위험지도, 지도 화면은 ISIMIP 격자, Studio는 방어 없는 ISIMIP다. 전국 50년 방어는 Models 탭 실행기(`runner.py`)가 홍수위험지도 값에까지 적용한다.
- **해안 침수:** 자산 평가의 대표 결과는 Aqueduct 50번째 백분위(전지구, 50년 방어, 금액 있음)이고, 조위 기준 연결 침수 계산은 국내 모델 행(금액 없음)이다. 지도 화면은 Aqueduct 50번째, Studio는 Aqueduct 95번째 백분위다.
- **폭염:** 자산 평가는 UTCI, 지도 화면은 폭염일수, Studio는 최고기온 95번째 백분위다.

목표는 재해마다 **전국에 한 가지 주 방법**을 쓰고, 모든 화면이 같은 표를 따르게 하는 것이다. 개별 결과로 되돌아가지 않도록 테스트로 막는다.

## 규칙 (사용자 결정 2026-11-16)

0. **1순위는 (재해, 모델, 자료)의 묶음으로 정한다.**
   - 자산 평가는 재해마다 세 모델(전지구, 국가 데이터, 국내)을 돌릴 수 있다.
   - 1순위가 아닌 모델의 행은 "참고"로 보인다. 대표값이나 합계에는 들어가지 않고, 1순위가 비어도 대신 채우지 않는다.
   - 지금 결과표의 `primary_row`(`results_table.py:417`)는 1순위가 비면 다른 모델 값으로 채운다. 이것부터 없앤다.

1. **주 방법은 순위로 적는다.**
   - 1순위만 결과로 쓴다.
   - 1순위를 쓸 수 없는 곳은 다른 순위로 채우지 않는다. 값은 NaN이고, 사유를 함께 남긴다.
   - 2순위 이하는 1순위 전체가 쓸 수 없게 됐을 때를 위한 기록이다.
2. **검증 방법도 순위로 적고, 그 순서대로 실행한다.**
   - 검증 결과는 기록만 하고 주 방법의 값을 바꾸지 않는다.
   - 기준을 넘는 차이가 나면 경고한다.
3. **보조 결과는 검증과 따로 둔다.**
   - 디스커션에만 쓴다.
   - 예: 질병청 온열질환자 수. 노출과 적응 수준이 들어 있어 하자드를 검증할 수 없다.
4. **"자료 없음"과 0을 구분한다.**
   - 사유는 세 가지로 나눈다.
     - `no_map`: 그 유역에 그 종류의 지도 파일이 없다.
     - `no_file_for_rp`: 그 빈도의 지도가 없다.
     - `map_unreadable`: 파일이 iCloud에만 있어 오프라인에서 열 수 없다.
   - 없는 빈도 자리에 다른 빈도의 값을 빌려 쓰지 않는다. 지금 100년 값을 200·500년에 빌려 쓰는 처리를 없앤다.
   - 결과 행마다 자산별 사유 칸을 둔다.
   - 일부 자산이 NaN이면 포트폴리오 합계는 "부분 합계(n/N)"로 표시한다.
   - 해당 유역의 지도 파일이 없으면 NaN이고, 사유는 `no_map`이다.
   - 지도가 있는 유역에서 폴리곤 밖이면 0 m다.
5. **한 재해 안에서 지역마다 다른 입력을 섞지 않는다.**
   - 예: 해안 지반고를 국토지리정보원 DEM(2도엽뿐)과 GLO-30으로 섞지 않는다.
   - 섞인 입력은 주 방법에서 빼고 검증으로 옮긴다.

6. **방어 가정은 1순위 지도 값을 바꾸지 않는다.**
   - 홍수위험지도는 제방이 무너지는 상황을 가정한 지도다. 그래서 전국 일괄 50년 방어를 적용하지 않는다.
   - 방어 가정은 참고 모델(ISIMIP, Aqueduct)에만 남긴다.

- 주 방법의 2순위 이하는 지금 비어 있다. 1순위를 "전체적으로 쓸 수 없다"는 판단은 자동으로 하지 않고 사용자가 한다.
- 검증의 "실행 순서"는 이런 뜻이다. 검증은 모두 실행하되 그 순서로 기록한다. 자료가 없어 돌리지 못한 검증은 이유와 함께 "건너뜀"으로 남긴다.
- 이 표에 없는 것은 "범위 밖 / 참고" 목록에 따로 적는다.
  - Studio의 나머지 10개 재해
  - 지도 화면의 산불·가뭄·LitPop 층
  - 디지털 트윈과 사례 연구
- 요청한 시나리오가 없어 다른 시나리오로 답한 경우(예: historical로 응답)도 행마다 기록한다.
- 폭염의 폭염일수는 2순위로 두지 않는다. 사용자 결정에 따라 빈 곳을 채우지 않기 때문이다.

## 무엇을 만드나

구현 순서 (검토 반영):
1. 등록표 (메타데이터만, 동작 변경 없음)
2. `primary_row` 대체 제거와 자산별 사유 칸
3. 검증 실행 틀 (실행함 / 건너뜀 / 경고)
4. 지도 범위표와 유역 경계
5. 지도 화면 (UTCI, 해안, 하천 폴리곤 순)
6. Studio 표시

1. **`assets/libraries/method_registry.json`**
   - 재해마다 `main`(순위 목록), `checks`(순위 목록), `supplementary`를 둔다.
   - 항목마다 `id`, 설명, 자료, 적용 범위, 쓸 수 없을 때의 처리, 출처를 적는다.
2. **로더 `src/climaterisk/physical_risk/method_registry.py`**
   - 기존 `worker/.../physical_risk/registry.py`는 영향함수 등록부라 이름이 겹치지 않게 한다.
   - `READINESS`, `recommended_models()`, `heat_utci.enabled`가 등록표와 어긋나면 테스트가 실패하게 한다. 또는 이 셋을 등록표에서 만든다.
   - 결과 행마다 `method_id`와 `method_rank`를 적는다.
   - 검증은 등록 순서대로 돌리고, 돈 것과 건너뛴 것(이유 포함)을 기록한다.
3. **테스트**
   - `method_id`는 결과를 쓰는 한 곳에서 찍는다. 자산 평가는 `_rows_for`, 지도 화면은 레이어 meta다.
   - 확인도 그 자리에서 한다. 기존 `readiness_matches_backend` 테스트를 넓힌다.
   - 등록표에 없는 방법이 결과에 나오면 실패한다.
4. **지도 없음 = NaN**
   - 표준유역 중권역 경계 폴리곤이 필요한데 디스크에 없다.
     - data.go.kr 15123324는 코드표(CSV 850행, 이용허락 제한 없음)라 경계가 들어 있지 않다.
     - 경계 자료를 찾아 출처와 라이선스를 확인한 뒤 하나만 받는다.
   - 지도 범위표는 파일 이름만으로 만든다. (유역, 지도 종류, 빈도)마다 있음 / 없음 / 열 수 없음을 적는다.
   - 하천 지도는 지방하천 100년 빈도뿐인 유역이 있고, 국가하천 100/200/500년 빈도가 유역마다 다르다. 이 구성을 결과에 함께 적는다.
5. **지도 화면 정렬**
   - **하천 홍수:** 홍수위험지도 폴리곤을 원형 그대로 그린다.
     - 사용자 결정(2026-11-16): 비영리 내부 용도로 사용자 컴퓨터 안에서만 본다. 수자원정보센터 답을 기다리지 않고 만든다.
     - 좌표는 화면에 그릴 때만 변환한다. 변환한 형상을 파일로 저장하거나, 격자로 바꾸거나, 시군구로 집계하지 않는다.
     - 지금 지도 화면은 미리 만든 `.board.json`을 읽으므로 하천은 별도 경로가 필요하다.
     - 미래 층은 빈도 변화율뿐이라 그릴 형상이 없다.
     - Windows 배포본에는 넣지 않는다.
     - ISIMIP 격자는 참고 층으로 내린다.
   - **폭염:** UTCI 층을 만들고 폭염일수 층은 검증으로 표시한다.
   - **해안:** 같은 원칙을 따른다.
   - 외부에 보이기 전에는 수자원정보센터(02-590-9977) 확인이 필요하다.
6. **Studio**
   - 등록표를 따르게 하거나, 따르기 전까지 "다른 방법(참고)"이라는 표시를 단다.
